# 家計簿アプリ 基本仕様書

## 1. アプリ概要
本アプリは、日々の収支をカレンダー形式で管理し、年間の収支を把握できるAndroid向け家計簿アプリケーションである。次の機能を特徴とする。

*   クレジットカードの「利用日」と「引き落とし日」を連動させた自動記帳と、二重計上を防ぐ集計ロジック
*   電子マネー等の支払方法ごとの残高管理（チャージ機能・残高修正機能）
*   サブスクリプション（月払い／年払い）の自動計上

## 2. 動作環境・技術スタック
*   **対象端末:** Android 15 (OPPO Reno11 A など)
*   **開発言語:** Kotlin
*   **UIフレームワーク:** Jetpack Compose (Material 3)
*   **アーキテクチャ:** MVVM (Model-View-ViewModel)
*   **ローカルデータベース:** Room Database (2.8.4) / KSP
*   **設定データ保存:** SharedPreferences
*   **外部通信:** 祝日API（`https://holidays-jp.github.io/api/v1/date.json`）の取得のみ

## 3. 画面構成

画面下部のボトムナビゲーションにより、3つのメイン画面（カレンダー／年間収支／設定）を切り替えて使用する。

### 3.1. カレンダー画面 (CalendarScreen)
*   **月別カレンダー表示:**
    *   「先月」「来月」ボタンで月を移動できる。月表示部分をタップすると、年月選択ダイアログ（2000〜2050年）から直接移動できる。
    *   マス目の高さはコンテンツ量に応じて動的に広がる設計（`heightIn`）で、金額の見切れを防ぐ。
    *   日曜・祝日の日付は赤、土曜は青で表示する。
*   **日別合計金額の表示（4色）:**
    *   **収入:** 青色（`+金額`）
    *   **通常支出:** 赤色（`-金額`）
    *   **クレジット利用分:** オレンジ色（`-金額`）
    *   **引落／チャージ:** 紫色（`±金額`）。カテゴリー「残高調整」は表示対象外。
*   **月間合計カード:** 画面下部に、その月の収入・支出・収支を表示する。
*   **日別詳細ダイアログ:**
    *   日付をタップすると、その日の明細リストと「収入合計」「支出合計」を表示する。
    *   FAB（+ボタン）から新規登録用ボトムシートを開く。
    *   手動登録データは編集・削除できる（削除時は確認ダイアログを表示）。
    *   クレジット引き落としデータは「自動計算」、サブスクデータは「自動生成」と表示され、直接の編集・削除はできない。

### 3.2. 取引入力フォーム（ボトムシート）
「収入」「支出」「チャージ」の3タブで構成される。

| タブ | 入力項目 | 備考 |
| :--- | :--- | :--- |
| 収入 | 内容、カテゴリー、金額 | 支払方法は「現金」固定 |
| 支出 | 支払方法、内容、カテゴリー、金額 | 支払方法が「クレジット」の場合、引き落としデータを自動生成 |
| チャージ | チャージ元、チャージ先、内容、金額 | チャージ先に「現金」は選べない。チャージ元が「クレジット」の場合は引き落としデータを自動生成 |

*   **残高チェック:** 「現金」「クレジット」以外の支払方法（電子マネー等）を使う支出・チャージ元に指定する場合、金額が残高を超えると保存できない。残高が0以下の支払方法はドロップダウンで選択不可になる。
*   **編集時の考慮:** 既存データの編集時は、そのデータ自身の金額を残高に戻して判定する。

### 3.3. 年間収支画面 (YearlySummaryScreen)
*   **年間サマリー:** 指定年の「年間収入合計」「年間支出合計」「年間収支」を表示する。
*   **年の切り替え:** 「前年」「翌年」ボタン、または年表示部分をタップして開く年選択ダイアログ（2000〜2050年）で変更する。
*   **月別リスト:** 1〜12月の収入・支出合計を表示する（収入・支出ともに0円の月は非表示）。
*   **集計ロジック:** システム設定に基づき、クレジットの「利用分」または「引き落とし分」のどちらか一方のみを集計する（4.3参照）。

### 3.4. 設定画面 (SettingsScreen)
*   **システム設定:**
    *   **クレジット支出の計算:** 支出合計に含めるタイミングを「利用日」「引き落とし日」から選択する。
    *   **引き落とし日:** 翌月の引き落とし日（1〜31日）を指定する。
    *   **休日の対応:** 引き落とし日が土日・祝日の場合の処理を「前倒し」「後倒し」から選択する。
*   **支払方法の設定:**
    *   支払方法（例: PayPay、Suica）の追加・削除ができる。
    *   「現金」「クレジット」は基本の支払方法として削除不可（`isDefault = true`）。
    *   「現金」「クレジット」以外には現在の残高を表示し、鉛筆アイコンから残高を修正できる（4.5参照）。
*   **サブスクリプション設定:**
    *   名前、金額、月払い／年払い、開始年月（年払いの場合は支払い月も）を登録する。
    *   登録済みサブスクの「編集」「削除」と、「解約」（終了年月の設定）・「修正」・「解約取消」ができる。
*   **カテゴリー設定:**
    *   カテゴリーの追加・削除ができる。
    *   初回起動時に「食費」「日用品」「交通費」「給料」「その他」が登録される。

## 4. 主要機能とビジネスロジック

### 4.1. クレジットカード連動機能
1.  支払方法「クレジット」で支出を登録する、またはチャージ元を「クレジット」にしてチャージを登録すると、そのデータが親（利用データ）となる。
2.  親データに対応する引き落としデータ（`isCreditPayment = true`、カテゴリー「口座引落」、支払方法「現金」、`parentTransactionId` に親のID）を自動生成して保存する。引き落とし日は「利用日の翌月の指定日」を休日調整したもの。
3.  親データを編集すると、引き落としデータも更新される。支払方法を変更して条件を満たさなくなった場合は、引き落としデータが削除される。
4.  親データを削除すると、引き落としデータも削除される。

### 4.2. 休日判定ロジック
*   引き落とし日が土曜・日曜、または祝日リストに含まれる場合、設定のポリシーに従って日付をずらす（前倒し＝1日ずつ戻す、後倒し＝1日ずつ進める）。平日になるまで繰り返す。
*   指定日が月の末日を超える場合（例: 31日指定で30日の月）は、その月の末日とする。
*   祝日リストは起動時に祝日APIから取得し、SharedPreferencesにキャッシュする。取得に失敗した場合はキャッシュを使い、キャッシュも無ければアプリ内蔵の2026年分の予備リストを使う。

### 4.3. 重複合算防止機能 (calculateTotalExpense)
クレジット機能を利用すると、データベース上には「利用日」と「引き落とし日」の2つの支出データが存在する。二重計上を防ぐため、`calculateTotalExpense` 拡張関数で次のように絞り込んでから合計する。

*   **共通:** チャージ（`isCharge = true`）は支出に含めない。サブスクの自動生成データ（`id < 0`）は常に含める。
*   **利用日合算設定時:** 自動生成された引き落としデータ（`isCreditPayment = true`）を除外する。
*   **引き落とし日合算設定時:** 支払方法が「クレジット」の利用データ（`paymentMethod == "クレジット" && !isCreditPayment`）を除外する。

収入は `!isExpense && !isCharge` のデータの合計である。

### 4.4. サブスクリプション自動計上
*   サブスクの情報はデータベースではなくSharedPreferences（JSON）に保存する。
*   表示対象の月ごとに、有効なサブスクを仮想の支出データとして生成する。DBには保存しない。
    *   対象月が「開始年月以降」かつ「終了年月以前（未設定なら無期限）」であること。
    *   年払いの場合は、対象月が支払い月と一致すること。
*   生成データの内容は、ID＝`-1000 - サブスクID`、カテゴリー「口座引落」、支払方法「現金」である。日付は、引き落とし日設定（当月の指定日）を休日調整した日になる。

### 4.5. 残高管理
*   支払方法ごとの残高は、全期間の取引から次の式で計算する（`calculateBalance`）。
    *   残高 ＝ チャージ入金 ＋ 収入 − チャージ出金 − 支出
    *   「現金」「クレジット」は残高管理の対象外（上限なし）。
*   **残高修正:** 設定画面で正しい残高を入力すると、差額を「残高調整」カテゴリーのチャージデータとして当日付で自動登録する。
    *   差額が正の場合：システム調整 → 該当の支払方法へのチャージ
    *   差額が負の場合：該当の支払方法 → システム調整へのチャージ
    *   これらは収支の集計には含まれず、カレンダーにも表示されない。

### 4.6. 既知の制約
*   **データベースの移行:** `fallbackToDestructiveMigration()` を使用しているため、スキーマのバージョンを上げると既存データはすべて消去される。
*   **クレジットからのチャージの集計:** チャージは支出に含めない仕様のため、「利用日合算」設定では、クレジットを元にしたチャージ分は支出として計上されない（引き落としデータが除外されるため）。
*   **名称での紐付け:** 取引は支払方法・カテゴリーを名前（文字列）で保持している。支払方法やカテゴリーを削除しても、既存の取引は変更されない。
*   **祝日の予備リスト:** アプリ内蔵の予備リストは2026年分のみ。

## 5. データベース設計 (Room Database - version 6)

### 5.1. transactions テーブル
| カラム名 | 型 | 制約・概要 |
| :--- | :--- | :--- |
| `id` | Int | Primary Key (Auto Generate) |
| `title` | String | 内容（品目名など） |
| `amount` | Int | 金額 |
| `isExpense` | Boolean | true=支出, false=収入 |
| `category` | String | カテゴリー名 |
| `date` | String | 日付（"yyyy-MM-dd" 形式） |
| `parentTransactionId` | Int? | 親データのID（クレジット引き落としデータ用） |
| `isCreditPayment` | Boolean | true=自動生成された引き落としデータ |
| `paymentMethod` | String | 支払方法名（初期値 "現金"）。チャージの場合はチャージ先 |
| `isCharge` | Boolean | true=チャージ（残高の移動。収支には含めない） |
| `chargeSource` | String? | チャージ元の支払方法名（チャージ以外は null） |

### 5.2. categories テーブル
| カラム名 | 型 | 制約・概要 |
| :--- | :--- | :--- |
| `id` | Int | Primary Key (Auto Generate) |
| `name` | String | カテゴリー名 |

### 5.3. payment_methods テーブル
| カラム名 | 型 | 制約・概要 |
| :--- | :--- | :--- |
| `id` | Int | Primary Key (Auto Generate) |
| `name` | String | 支払方法名 |
| `isDefault` | Boolean | true=削除不可（「現金」「クレジット」） |

## 6. SharedPreferences 保存項目
ファイル名: `kakeibo_prefs`

| キー名 | 初期値 | 概要 |
| :--- | :--- | :--- |
| `aggregate_credit_on_usage` | `true` | true=利用日で合算, false=引き落とし日で合算 |
| `credit_payment_day` | `27` | 翌月の引き落とし指定日（1〜31） |
| `credit_holiday_policy` | `"backward"` | 休日対応（"forward"=前倒し, "backward"=後倒し） |
| `saved_holidays_json` | なし | 祝日APIから取得した祝日データのキャッシュ |
| `subscriptions_json` | `[]` | サブスク一覧（JSON配列: id, name, amount, isYearly, billingMonth, startYearMonth, endYearMonth） |
