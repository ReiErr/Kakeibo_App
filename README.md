# 家計簿アプリ 基本仕様書

## 1. アプリ概要
本アプリは、日々の収支をカレンダー形式で管理し、年間の収支を把握できるAndroid向け家計簿アプリケーションである。特に、クレジットカードの「利用日」と「引き落とし日」を連動させた自動記帳機能と、二重計上を防止する集計ロジックを備えていることを特徴とする。

## 2. 動作環境・技術スタック
*   **対象端末:** Android 15 (OPPO Reno11 A など)
*   **開発言語:** Kotlin
*   **UIフレームワーク:** Jetpack Compose (Material 3)
*   **アーキテクチャ:** MVVM (Model-View-ViewModel)
*   **ローカルデータベース:** Room Database (2.8.4) / KSP
*   **設定データ保存:** SharedPreferences

## 3. 画面構成

本アプリは、画面下部のボトムナビゲーションにより3つのメイン画面を切り替えて使用する。

### 3.1. カレンダー画面 (CalendarScreen)
*   **月別カレンダー表示:**
    *   月ごとにカレンダーを表示し、「先月」「来月」ボタンで遷移可能。
    *   マス目の高さはコンテンツ量に応じて動的に広がる設計（`heightIn`）を採用し、金額の見切れを防止。
*   **日別合計金額の表示（色分け機能）:**
    *   日ごとの合計金額を4色に分類してカレンダー上に直接表示する。
    *   **収入:** 青色 (`Color.Blue`)
    *   **通常支出:** 赤色 (`Color.Red`)
    *   **クレジット利用分:** オレンジ色 (`Color(0xFFF57C00)`)
    *   **クレジット引き落とし分:** 紫色 (`Color(0xFF6A1B9A)`)
*   **日別詳細ダイアログ:**
    *   カレンダーの日付をタップすると、その日の明細リストを表示する。
    *   ダイアログ上部には、システム設定（重複合算防止）に基づいたその日の「収入合計」「支出合計」を表示する。
    *   自動生成された引き落としデータ（紫色）以外は、リストから直接「編集」「削除」が可能。
    *   FAB（+ボタン）から新規登録用ボトムシートを呼び出せる。

### 3.2. 年間収支画面 (YearlySummaryScreen)
*   **年間サマリー:** 指定した年の「年間収入合計」「年間支出合計」「年間収支（残高）」を表示する。
*   **月別リスト:** 1月〜12月までの各月の収入・支出合計をリスト表示する（データが0円の月は非表示）。
*   **集計ロジック:** システム設定（重複合算防止）に基づき、クレジットの「利用分」または「引き落とし分」のどちらか一方のみを集計に含める。

### 3.3. 設定画面 (SettingsScreen)
*   **システム設定:**
    *   **クレジット支出の計算:** 支出合計に含めるタイミングを「利用日」か「引き落とし日」から選択（トグルスイッチ）。
    *   **引き落とし日の設定:** 翌月の引き落とし日（1〜31日）を指定。
    *   **休日の対応:** 引き落とし日が土日・祝日に重なった場合の処理を「前倒し」「後倒し」から選択。
*   **カテゴリー設定:**
    *   新規カテゴリーの追加。
    *   登録済みカテゴリーの一覧表示と削除（「食費」「日用品」など）。
    *   システム上必須である「クレジット」カテゴリーは削除不可とし、代わりに入力画面での「表示ON/OFF」を切り替えるスイッチを提供する。

## 4. 主要機能とビジネスロジック

### 4.1. クレジットカード連動機能
1.  ユーザーがカテゴリー「クレジット」で支出を登録すると、該当データを親（`parentTransactionId`）として保持する。
2.  親データに基づいて、設定された「翌月の引き落とし日」に合わせた引き落としデータ（`isCreditPayment = true`）を裏側で自動生成し、データベースに保存する。
3.  親データ（利用分）が編集・削除された場合、連動して自動生成された引き落としデータも更新・削除される（道連れ更新/削除）。

### 4.2. 休日判定ロジック
*   引き落とし日の算出時、該当日が土曜日、日曜日、または指定された日本の祝日リストに含まれているかを判定する。
*   休日に該当する場合は、設定画面で指定されたポリシー（前倒し＝マイナス1日、後倒し＝プラス1日）に従い、平日になるまで日付をシフトさせる。

### 4.3. 重複合算防止機能 (calculateTotalExpense)
*   クレジット機能を利用すると、データベース上には「利用日」と「引き落とし日」の2つの支出データが存在することになる。
*   家計簿の二重計上を防ぐため、`calculateTotalExpense` 拡張関数を使用し、設定に応じて以下のフィルタリングを行ってから `sumOf` で合計を算出する。
    *   **利用日合算設定時:** `isCreditPayment = true`（自動生成された引き落としデータ）を合計から除外する。
    *   **引き落とし日合算設定時:** `category == "クレジット" && !isCreditPayment`（利用データ）を合計から除外する。

## 5. データベース設計 (Room Database - version 3)

### 5.1. transactions テーブル
| カラム名 | 型 | 制約・概要 |
| :--- | :--- | :--- |
| `id` | Int | Primary Key (Auto Generate) |
| `title` | String | 内容（品目名など） |
| `amount` | Int | 金額 |
| `isExpense` | Boolean | true=支出, false=収入 |
| `category` | String | カテゴリー名 |
| `date` | String | 登録日（"yyyy-MM-dd" 形式） |
| `parentTransactionId` | Int? | 親データのID（クレジット引き落としデータ用） |
| `isCreditPayment` | Boolean | true=自動生成された引き落としデータ |

### 5.2. categories テーブル
| カラム名 | 型 | 制約・概要 |
| :--- | :--- | :--- |
| `id` | Int | Primary Key (Auto Generate) |
| `name` | String | カテゴリー名 |
| `isDefault` | Boolean | true=削除不可（システム必須カテゴリー保護用） |
| `isVisible` | Boolean | true=入力フォームのドロップダウンに表示する |

## 6. SharedPreferences 保存項目
| キー名 | 初期値 | 概要 |
| :--- | :--- | :--- |
| `aggregate_credit_on_usage` | `true` | true=利用日で合算, false=引き落とし日で合算 |
| `credit_payment_day` | `27` | 翌月の引き落とし指定日（1〜31） |
| `credit_holiday_policy` | `"backward"` | 休日対応（"forward"=前倒し, "backward"=後倒し） |
