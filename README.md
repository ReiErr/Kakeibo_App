# 家計簿アプリ (KakeiboApp) 仕様書兼README

日々の収支をカレンダー形式で直感的に管理し、年間収支の把握や決済手段ごとの残高管理、サブスクリプション、クレジットカードの引き落とし連動までをスマートに行えるAndroid向け家計簿アプリケーションです。

---

## 1. アプリ概要

「KakeiboApp」は、現金支払いに加えて、キャッシュレス決済（電子マネー・クレジットカード）や定期的なサブスクリプションの利用が増えた現代の支出管理に最適化された家計簿アプリです。

### 主な特長
- **カレンダー直感管理**: 日別の収支を4色の明細バッジで視覚的に把握。日本の祝日・土日判定に対応。
- **クレジットカード完全連動**: クレジット利用時に翌月の引き落とし日（休日シフト対応）のデータを自動生成し、利用日・引き落とし日どちらの集計基準でも二重計上を防止。
- **電子マネー残高 & チャージ管理**: PayPayやSuicaなどの電子マネー残高を自動計算。現金やクレジットからのチャージにも対応し、残高不足バリデーションや残高の直接修正も完備。
- **サブスクリプション自動反映**: 月払い・年払いの固定費を登録しておくだけで、DBを汚さずにカレンダー・年間収支へ仮想取引として自動反映。
- **年間収支の可視化**: 1〜12月の月別収支や年間合計を素早く把握。

## 3. 画面構成と機能詳細

アプリ下部のナビゲーションバー（NavigationBar）により、以下の3つの主要画面を切り替えます。

```
[MainActivity]
  ├── [カレンダー] (CalendarScreen)
  ├── [年間収支] (YearlySummaryScreen)
  └── [設定] (SettingsScreen)
```

### 3.1. カレンダー画面 (`CalendarScreen`)
- **月別カレンダービュー**:
  - 先月 / 来月ボタン、および年月部分のタップで起動するドラムロール風 **年月ピッカーダイアログ (`YearMonthPickerDialog`)** による素早い月移動。
  - セル内のコンテンツ量に応じて動的に広がる設計（`heightIn(min = 85.dp)`）で、金額の見切れを防止。
  - 日付カラー判定：平日（黒）、土曜日（青）、日曜日および日本の祝日（赤）。
- **日別合計金額の4色バッジ表示**:
  - 🟦 **収入**: `Color.Blue` (`+金額`)
  - 🟥 **通常支出**: `Color.Red` (`-金額`)
  - 🟧 **クレジット利用**: `CreditColor (0xFFF57C00)` (`-金額`)
  - 🟪 **口座引落 / チャージ**: `ChargeColor (0xFF6A1B9A)` (`±金額`)
- **月間サマリーカード**:
  - 選択中の月の「収入」「支出」「収支（収入 - 支出）」をリアルタイム集計表示。
- **日別詳細ダイアログ (`DailyDetailDialog`)**:
  - 日付セルタップで起動。その日の取引一覧、収入合計、支出合計を表示。
  - FAB（＋ボタン）から新規登録ボトムシートを起動。
  - 通常取引の「編集」「削除」に対応（自動生成された引き落としデータやサブスクデータは誤操作防止のため保護）。

### 3.2. 年間収支画面 (`YearlySummaryScreen`)
- **年間サマリーカード**:
  - 指定された年の「年間収入」「年間支出」「年間収支」を表示。
- **年ピッカー (`YearPickerDialog`)**:
  - 年表示タップで西暦を直接選択可能。
- **月別明細リスト**:
  - 1月〜12月までの各月の収入・支出を一覧表示（収支が発生している月のみ表示）。

### 3.3. 取引入力ボトムシート (`TransactionInputForm`)
タブ切り替えにより3種類の記帳に対応：
1. **「収入」タブ**:
   - 内容、カテゴリー、金額を入力。
2. **「支出」タブ**:
   - 支払方法（現金、クレジット、登録済み電子マネー）、内容、カテゴリー、金額を入力。
   - 電子マネー選択時は、**現在の利用可能残高を超えた支出を防止するバリデーション**が作動。
3. **「チャージ」タブ**:
   - チャージ元（現金、クレジット、電子マネー）とチャージ先（電子マネー）を選択。
   - チャージ元が電子マネーの場合、残高不足バリデーションが作動。
   - チャージ元がクレジットカードの場合、**クレジットの引き落としデータが自動生成**されます。

### 3.4. 設定画面 (`SettingsScreen`)
- **システム設定**:
  - **クレジット支出の計算基準**: 支出合計に含めるタイミングを「利用日」または「引き落とし日」から選択。
  - **引き落とし日**: 翌月の引き落とし日（1〜31日）を指定。
  - **休日の対応**: 引き落とし日が土日・祝日の場合のシフト方向を「前倒し（前営業日）」または「後倒し（翌営業日）」から選択。
- **支払方法の設定 & 残高管理**:
  - 新規支払方法（PayPay、Suica等）の追加。
  - 登録済み支払方法の一覧と、現在の保有残高（リアルタイム算出）の確認。
  - **残高修正機能**: 実残高とのズレが生じた場合、ダイアログから正しい残高を入力すると差額を「残高調整」取引として自動起票。
  - デフォルト決済手段（現金、クレジット）以外の削除。
- **サブスクリプション設定**:
  - サブスクの追加（サービス名、金額、月々払い/年払い、支払い月、利用開始年月）。
  - サブスクの一覧表示、編集、解約（解約年月の指定 / 解約取消）、削除。
- **カテゴリー設定**:
  - カテゴリーの新規追加・削除。

## 4. 主要なビジネスロジック

### 4.1. クレジットカード連動 & 自動引き落とし生成
- **親取引と引き落とし取引の自動生成**:
  - クレジット支払いで支出を登録、またはクレジットから電子マネーにチャージすると、翌月の引き落とし日に合わせた引き落としデータ（`isCreditPayment = true`）をバックグラウンドで自動登録します。
- **追従更新 / 道連れ削除**:
  - 元の親取引の金額や日付が変更された場合、引き落とし日・金額も自動再計算・更新されます。
  - 親取引を削除すると、紐付く引き落としデータも自動で削除されます。
  - 支払方法をクレジット以外に変更した場合は、引き落としデータが自動消去されます。

### 4.2. 祝日判定 & 銀行営業日シフトロジック
- **祝日データ取得**:
  - アプリ起動時に日本の祝日API（Holidays JP API）から最新の祝日一覧を取得し、SharedPreferencesにキャッシュ。オフライン時や通信失敗時はキャッシュまたは2026年予備リストへフォールバック。
- **引き落とし日の営業日補正**:
  - 翌月の引き落とし指定日（月末日を超える場合は月末日へ補正）が土曜日、日曜日、祝日であるかを判定。
  - 「前倒し（forward）」なら平日になるまで日付をマイナス、「後倒し（backward）」なら平日になるまで日付をプラスして最終的な引き落とし日を決定します。

### 4.3. 二重計上防止ロジック (`calculateTotalExpense`)
クレジット決済を記録すると、データベース内には「利用日」と「引き落とし日」の双方が存在します。
集計の二重計上を防ぐため、設定（`aggregateCreditOnUsageDate`）に応じて以下のようにフィルタリングします：
- **利用日で合算する場合**: 自動生成された引き落としデータ（`isCreditPayment == true`）を除外。
- **引き落とし日で合算する場合**: クレジットの利用データ（`paymentMethod == "クレジット"` かつ `!isCreditPayment`）を除外。
- チャージデータ（`isCharge == true`）は資金移動であるため、支出・収入の合計からは常に除外されます。

### 4.4. サブスクリプションの仮想取引生成 (`isVirtual`)
- サブスクリプションは毎月の取引テーブルを無駄に肥大化させないため、Room DBではなくSharedPreferences（JSON）に設定として保存。
- カレンダーや年間収支の表示時に、対象月・開始月・解約月・年払い指定月を評価し、**負のIDを持つ仮想の取引データ（Virtual Transaction）** として動的に生成・合算します。

### 4.5. 決済残高の動的計算 (`calculateBalance`)
全期間の取引から以下の計算式で各決済手段の残高を瞬時に算出します：
$$\text{残高} = (\text{チャージ入金} + \text{収入}) - (\text{チャージ出金} + \text{支出})$$
※現金・クレジットは残高上限なし（`Int.MAX_VALUE`）として扱います。

## 5. データ設計

### 5.1. Room Database (version 6)

#### `transactions` テーブル
| カラム名 | 型 | NULL許容 | 概要 |
| :--- | :--- | :---: | :--- |
| `id` | Int | NO | 主キー（自動採番） |
| `title` | String | NO | 摘要・品目名 |
| `amount` | Int | NO | 金額 |
| `isExpense` | Boolean | NO | `true`: 支出, `false`: 収入 |
| `category` | String | NO | カテゴリー名 |
| `date` | String | NO | 取引日付 (`yyyy-MM-dd`) |
| `parentTransactionId` | Int | YES | クレジット引き落としデータの親取引ID |
| `isCreditPayment` | Boolean | NO | クレジットの引き落としデータフラグ |
| `paymentMethod` | String | NO | 支払方法名（デフォルト: `"現金"`） |
| `isCharge` | Boolean | NO | チャージ取引フラグ |
| `chargeSource` | String | YES | チャージ元の支払方法名 |

#### `categories` テーブル
| カラム名 | 型 | NULL許容 | 概要 |
| :--- | :--- | :---: | :--- |
| `id` | Int | NO | 主キー（自動採番） |
| `name` | String | NO | カテゴリー名（初期値: 食費, 日用品, 交通費, 給料, その他） |

#### `payment_methods` テーブル
| カラム名 | 型 | NULL許容 | 概要 |
| :--- | :--- | :---: | :--- |
| `id` | Int | NO | 主キー（自動採番） |
| `name` | String | NO | 決済手段名 |
| `isDefault` | Boolean | NO | `true`: 基本決済手段（「現金」「クレジット」は削除不可） |

---

### 5.2. SharedPreferences (`kakeibo_prefs`)

| キー | 型 | デフォルト値 | 概要 |
| :--- | :--- | :--- | :--- |
| `aggregate_credit_on_usage` | Boolean | `true` | クレジット支出の集計タイミング（`true`: 利用日, `false`: 引き落とし日） |
| `credit_payment_day` | Int | `27` | クレジットの引き落とし日（1〜31） |
| `credit_holiday_policy` | String | `"backward"` | 休日時のシフト方針（`"forward"`: 前倒し, `"backward"`: 後倒し） |
| `saved_holidays_json` | String | なし | 取得済み祝日データのJSON文字列 |
| `subscriptions_json` | String | `"[]"` | 登録されたサブスクリプション一覧のJSON配列 |

## 7. ビルド & 実行方法

1. **Android Studio** で本プロジェクトフォルダを開きます。
2. Gradle Sync が完了するのを確認します。
3. Android 15 (API Level 35以上) の実機またはエミュレータを起動します。
4. `Run 'app'` を実行します。
