# 家計簿アプリ (KakeiboApp) 仕様書兼README

日々の収支をカレンダー形式で直感的に管理し、月間・年間の収支把握や円グラフによる支出分析、複数クレジットカードや電子マネーの残高管理、サブスクリプション自動反映、確定請求額の端数調整、全データJSONバックアップまでをスマートに行えるAndroid向け家計簿アプリケーションです。

---

## 1. アプリ概要

「KakeiboApp」は、現金支払いに加えて、キャッシュレス決済（電子マネー・複数クレジットカード）や定期的なサブスクリプションの利用が増えた現代の支出管理に最適化された家計簿アプリです。

### 主な特長
- **カレンダー直感管理**: 日別の収支を4色の明細バッジで視覚的に把握。日本の祝日・土日判定に対応。
- **クレジットカード完全連動 & 確定請求額の端数調整**:
  - カードごとの個別締め日・支払月オフセット・引き落とし日・休日シフト設定に対応。
  - カレンダーの引き落とし明細から「確定請求額」を入力して差額を自動調整（ポイント値引き等は支出合計から直接減額）。
- **電子マネー残高 & チャージ管理**: PayPayやSuicaなどの電子マネー残高を自動計算。チャージ連動、残高不足防止、手動残高修正を完備。
- **サブスクリプション自動反映**: 月払い・年払いの固定費を登録しておくだけで、DBを汚さずに指定カードの引き落とし日に合わせてカレンダーや収支へ仮想取引として自動反映。
- **円グラフ支出分析**: 月ごとのカテゴリー別・決済手段別の支出割合を視覚的に分析。
- **月間・年間収支サマリー**:
  - 「月間収支」と「年間収支」をワンタップで切り替え。
  - 月間合計・カテゴリー別内訳・日別推移の一覧表示、および年間一覧からの月タップドリルダウンに対応。
- **データ管理（CSV出力 & 完全バックアップ・復元）**:
  - 取引履歴のCSVエクスポート。
  - アプリ内の全設定・全データを一括保存・復元できるJSONバックアップ＆インポート機能を搭載。

## 3. 画面構成と機能詳細

アプリ下部のナビゲーションバー（NavigationBar）により、4つの主要画面をスムーズに切り替えます。

```
[MainActivity]
  ├── [カレンダー] (CalendarScreen)
  ├── [分析]       (AnalysisScreen)
  ├── [収支]       (YearlySummaryScreen)
  └── [設定]       (SettingsScreen)
```

### 3.1. カレンダー画面 (`CalendarScreen`)
- **月別カレンダービュー**:
  - 先月 / 来月ボタン、および年月タップで起動するドラムロール風 **年月ピッカーダイアログ (`YearMonthPickerDialog`)** による素早い移動。
  - セル内のコンテンツ量に応じて動的に広がる設計（`heightIn(min = 85.dp)`）で、金額の見切れを防止。
  - 日付カラー判定：平日（黒）、土曜日（青）、日曜日および日本の祝日（赤）、当日の青枠ハイライト。
- **日別合計金額のバッジ表示**:
  - 🟦 **収入**: `Color.Blue` (`+金額`)
  - 🟥 **通常支出**: `Color.Red` (`-金額`)
  - 🟩 **マイナス支出（割引等）**: `Color(0xFF2E7D32)` (`-金額`)
  - 🟧 **クレジット利用**: `CreditColor (0xFFF57C00)` (`-金額`)
  - 🟪 **口座引落 / チャージ**: `ChargeColor (0xFF6A1B9A)` (`±金額`)
- **月間サマリーカード**:
  - 選択中の月の「収入合計」「支出合計」「収支差額（収入 - 支出）」をリアルタイム集計表示。
- **日別詳細ダイアログ (`DailyDetailDialog`)**:
  - 日付セルタップで起動。その日の取引一覧、収入・支出合計を表示。
  - 最下部に固定配置された押しやすい「＋ 収支を追加」ボタン（リストと被らない安全設計）。
  - 各行の「編集」「削除」に対応。
  - クレジット引き落とし行には**「調整」ボタン**が表示され、実際のカード確定請求額を入力して端数調整取引を自動起票可能。

### 3.2. 分析画面 (`AnalysisScreen`)
- **月別支出割合の可視化**:
  - 年月ピッカーにより対象月を素早く切り替え。
  - **カテゴリー別 円グラフ**: 食費、日用品、固定費などの支出比率を色鮮やかなドーナツチャートで描画。
  - **決済手段別 円グラフ**: 現金、電子マネー、各クレジットカード等の利用比率を可視化。
  - 各項目の金額・構成比率（%）の一覧表示。

### 3.3. 収支サマリー画面 (`YearlySummaryScreen`)
上部のタブにより「月間収支」と「年間収支」を切り替え可能。
- **「月間収支」タブ**:
  - 月間合計カード（収入・支出・収支差額）。
  - **カテゴリー別内訳**: 支出および収入のカテゴリーごとの合計額を降順表示。
  - **日別明細**: 取引があった日ごとに収入、支出、日別収支を一覧表示。
- **「年間収支」タブ**:
  - 年間合計カード（年間収入・年間支出・年間収支）。
  - **月別明細リスト (1〜12月)**: 各月の収入・支出に加え、**「各月の収支差額」**（プラスは青、マイナスは赤）を表示。
  - **月タップドリルダウン**: 特定の月をタップすると、自動で「月間収支」タブに切り替わりその月の詳細画面へ遷移。

### 3.4. 取引入力ボトムシート (`TransactionInputForm`)
スクロール不要のコンパクトな1画面設計で直感的に入力可能：
1. **「支出」タブ**:
   - 支払方法（現金、クレジット、登録済み電子マネー等）、内容、カテゴリー（支出専用カテゴリのみ表示）、金額、メモを入力。
   - 電子マネー選択時は、現在の利用可能残高を超えた支出を防止するバリデーションが作動。
2. **「収入」タブ**:
   - 入金先（現金、銀行口座等）、内容、カテゴリー（収入専用カテゴリのみ表示）、金額、メモを入力。
3. **「チャージ」タブ**:
   - チャージ元（現金、クレジット、電子マネー等）とチャージ先を選択。
   - チャージ元がクレジットの場合、対応する引き落としデータが自動生成されます。

### 3.5. 設定画面 (`SettingsScreen`)
- **データ管理**:
  - **CSVエクスポート**: 取引データのCSV出力。
  - **全データ バックアップ (JSON)**: 取引・カテゴリ・決済手段・サブスク・設定を丸ごとJSONファイルとしてエクスポート。
  - **復元 (インポート)**: バックアップJSONファイルを読み込んで完全リストア（確認ダイアログ付き）。
- **システム設定**:
  - クレジット支出の集計基準（「利用日」または「引き落とし日」）。
- **決済手段の設定 & 残高管理**:
  - クレジットカードの個別登録・編集（カード名、締め日、引き落とし月オフセット、引き落とし日、休日シフト方針）。
  - 電子マネー等の追加・削除。
  - **残高修正機能**: 実残高とのズレが生じた場合、ダイアログから正しい残高を入力して「残高調整」取引を自動登録。
- **サブスクリプション設定**:
  - サブスクの追加・編集（サービス名、金額、月々/年払い、支払月、開始年月、**決済手段の紐付け**、**カテゴリーの紐付け**）。
  - 紐づけられた決済手段（クレジットカード等）の引き落とし日・休日設定に基づいて個別スケジュール計算。
  - 解約年月設定 / 解約取消。
- **カテゴリー設定**:
  - 支出用・収入用を分離したカテゴリー追加・削除。

## 4. 主要なビジネスロジック

### 4.1. クレジットカード連動 & 端数調整
- **親取引と引き落とし取引の自動生成**:
  - クレジット決済時、またはクレジットチャージ時に、指定されたカードの「締め日」「支払月」「引き落とし日」「休日シフト」に従って引き落としデータ（`isCreditPayment = true`）を自動生成。
- **追従更新 / 道連れ削除**:
  - 親取引の金額・日付変更に引き落としデータが自動追従。親取引削除時は引き落としデータも自動削除。
- **確定請求額の端数調整**:
  - カレンダーから実際の請求額を入力すると差額を自動計算。
  - 請求額が高い場合：差額を「端数調整（手数料等）」として支出計上。
  - 請求額が安い場合（ポイント値引き等）：収入を増やさず「端数調整（クレジット割引）」として**負の金額の支出（支出減額）**を計上し、支出合計を直接減額。

### 4.2. 祝日判定 & 銀行営業日シフトロジック
- **祝日データ取得**:
  - アプリ起動時に日本の祝日API（Holidays JP API）から祝日一覧を取得・キャッシュ。
- **引き落とし日の営業日補正**:
  - 指定引き落とし日が土日・祝日の場合、設定に応じて「前倒し（前営業日）」または「後倒し（翌営業日）」へ自動補正。

### 4.3. 二重計上防止ロジック (`calculateTotalExpense`)
- **利用日で合算する場合**: 自動生成された引き落としデータ（`isCreditPayment == true`）を除外。
- **引き落とし日で合算する場合**: クレジットの利用データ（`paymentMethod` がクレジット種別かつ `!isCreditPayment`）を除外。
- チャージデータ（`isCharge == true`）は資金移動であるため、常に支出・収入の合計から除外。

### 4.4. サブスクリプションの仮想取引生成 (`isVirtual`)
- サブスク情報は SharedPreferences に保持。
- カレンダー・収支画面の描画時に、開始月・解約月・年払い指定月および紐づくカードの支払日を評価し、**負のIDを持つ仮想取引（Virtual Transaction）**として動的に生成・合算。

### 4.5. 決済残高の動的計算 (`calculateBalance`)
全期間の取引から以下の計算式で各決済手段の残高を瞬時に算出：
$$\text{残高} = (\text{チャージ入金} + \text{収入}) - (\text{チャージ出金} + \text{支出})$$
※残高管理対象外の決済手段は `Int.MAX_VALUE` として扱います。

## 5. データ設計

### 5.1. Room Database (version 10)

#### `transactions` テーブル
| カラム名 | 型 | NULL許容 | 概要 |
| :--- | :--- | :---: | :--- |
| `id` | Int | NO | 主キー（自動採番） |
| `title` | String | NO | 摘要・品目名 |
| `amount` | Int | NO | 金額（負の数で支出減額にも対応） |
| `isExpense` | Boolean | NO | `true`: 支出, `false`: 収入 |
| `category` | String | NO | カテゴリー名 |
| `date` | String | NO | 取引日付 (`yyyy-MM-dd`) |
| `parentTransactionId` | Int | YES | クレジット引き落としデータの親取引ID |
| `isCreditPayment` | Boolean | NO | クレジットの引き落としデータフラグ |
| `paymentMethod` | String | NO | 支払方法名 |
| `isCharge` | Boolean | NO | チャージ取引フラグ |
| `chargeSource` | String | YES | チャージ元の支払方法名 |
| `memo` | String | NO | 詳細メモ |

#### `categories` テーブル
| カラム名 | 型 | NULL許容 | 概要 |
| :--- | :--- | :---: | :--- |
| `id` | Int | NO | 主キー（自動採番） |
| `name` | String | NO | カテゴリー名 |
| `isExpense` | Boolean | NO | `true`: 支出用, `false`: 収入用 |

#### `payment_methods` テーブル
| カラム名 | 型 | NULL許容 | 概要 |
| :--- | :--- | :---: | :--- |
| `id` | Int | NO | 主キー（自動採番） |
| `name` | String | NO | 決済手段名 |
| `isDefault` | Boolean | NO | 削除不可フラグ |
| `type` | String | NO | 決済種別（`credit`, `cash`, `electronic_money`, `bank` 等） |
| `manageBalance` | Boolean | NO | 残高管理対象フラグ |
| `closingDay` | Int | NO | 締め日 (0=月末, 1〜31) |
| `paymentDay` | Int | NO | 引き落とし日 (1〜31) |
| `paymentMonthOffset` | Int | NO | 引き落とし月オフセット (1=翌月, 2=翌々月) |
| `holidayPolicy` | String | NO | 休日対応方針 (`forward`: 前倒し, `backward`: 後倒し) |

## 7. ビルド & 実行方法

1. **Android Studio** で本プロジェクトフォルダを開きます。
2. Gradle Sync が完了するのを確認します。
3. Android 15 (API Level 35以上) の実機またはエミュレータを起動します。
4. `Run 'app'` を実行します。
